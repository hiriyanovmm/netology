## Общее предложение

Для микросервисной платформы предлагаю связку **GitLab + GitLab CI/CD, Fluent Bit + Kafka + OpenSearch + OpenSearch Dashboards, Prometheus + Grafana + Alertmanager. 


## Задача 1: Разработка и CI/CD

### Решение

| Компонент | Роль |
|---|---|
| **GitLab** | Git-репозитории, проекты, права доступа, MR, реестр Docker-образов, переменные и секреты |
| **GitLab CI/CD** | Описание пайплайнов, шаблоны, ручные задачи, параллельные jobs |
| **GitLab Runner** | Исполнители сборок: облачные и self-hosted |
| **GitLab Container Registry** | Хранение образов приложений и CI-образов |
| **Vault / GitLab Secrets Manager** | Централизованное хранение секретов для чувствительных окружений |

GitLab использует Git как систему контроля версий; для каждого микросервиса создается отдельный репозиторий. В каждом репозитории хранится файл `.gitlab-ci.yml`, который описывает этапы сборки, тестирования, публикации образа и развертывания. 


### Обоснование

GitLab выбран как единая платформа: он объединяет Git, CI/CD, Container Registry, права доступа, секреты и аудит в одном продукте. Это снижает количество интеграций и упрощает сопровождение. GitLab Runner позволяет выполнять сборки как в облаке, так и на собственных серверах


## Задача 2: Централизованные логи

### Решение

| Компонент | Роль |
|---|---|
| **Fluent Bit** | Агент на каждом хосте/ноде Kubernetes; читает stdout/stderr контейнеров и файлы логов |
| **Kafka** | Буфер и гарантированная доставка при недоступности хранилища |
| **OpenSearch** | Центральное хранилище, индексация и полнотекстовый поиск |
| **OpenSearch Dashboards** | Веб-интерфейс для разработчиков, фильтры, сохраненные поиски, дашборды |

### Принцип работы

1. Приложение пишет логи в `stdout`/`stderr`
2. Fluent Bit собирает логи из container runtime (`/var/log/containers`, journald или файлы приложений).
3. Агент добавляет метаданные: `service`, `pod`, `namespace`, `host`, `environment`, `trace_id`, уровень лога.
4. События отправляются в Kafka.
5. OpenSearch ingest-ноды или отдельный consumer читают события из Kafka, парсят JSON и пишут в индексы.
6. Разработчики работают в OpenSearch Dashboards.

### Обоснование

Связка Fluent Bit + Kafka + OpenSearch отделяет сбор логов от их хранения и анализа. Kafka устраняет потерю событий при кратковременной недоступности хранилища и сглаживает пиковые нагрузки. OpenSearch хорошо подходит для поиска по большому объему полуструктурированных логов, а Dashboards дает разработчикам самостоятельный доступ без выдачи доступа к серверам.


## Задача 3: Мониторинг

### Решение

| Компонент | Роль |
|---|---|
| **Prometheus** | Сбор и хранение метрик, запросы PromQL |
| **Node Exporter** | Метрики хостов: CPU, RAM, диск, сеть |
| **cAdvisor / kube-state-metrics** | Метрики контейнеров и Kubernetes-объектов |
| **Приложение + клиентская библиотека** | Экспорт бизнес- и технических метрик сервиса |
| **Grafana** | Панели, дашборды, доступ команд |
| **Alertmanager** | Алерты в Slack, почту, и т. п. |

### Принцип работы

- На каждом хосте работает **Node Exporter**, который отдает метрики CPU, памяти, дисков, файловых систем и сети в формате Prometheus. 
- Для контейнеров используется **cAdvisor**: он предоставляет метрики потребления CPU, RAM, диска и сети на уровне контейнера.
- Каждый микросервис экспонирует endpoint `/metrics` с метриками: RPS, latency, ошибки, размер очередей, число соединений, время запросов к БД, бизнес-счетчики.
- Prometheus по расписанию опрашивает endpoints через service discovery: Kubernetes, Consul, статические targets или облачный provider.
- Grafana подключается к Prometheus как data source и строит дашборды с PromQL-запросами и агрегациями. 
- Alertmanager получает alerts от Prometheus и маршрутизирует их по severity, команде и окружению.

### Обоснование

Prometheus + Grafana — стандартный стек для мониторинга инфраструктуры. Он использует pull-модель, легко масштабируется, а PromQL дает гибкий поиск по сервису, окружению, ноде и версии. Node Exporter закрывает host-level метрики, cAdvisor — контейнерные, а Grafana предоставляет готовые и кастомные дашборды.

## Итоговая архитектура

```text
Разработчик
   │  Git push / MR / manual run
   ▼
GitLab + GitLab CI + Runners
   │  build, test, scan, publish image
   ▼
Container Registry → Kubernetes / VM
   │
   ├── stdout/stderr → Fluent Bit → Kafka → OpenSearch → Dashboards
   │
   └── /metrics → Prometheus → Grafana / Alertmanager
```
